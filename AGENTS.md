# Cinema Project — Agent Instructions

Before making any changes, read these files completely:

1. `CINEMA_PROJECT_SPEC.md` — product requirements, architecture, database, APIs, UX, and acceptance criteria.
2. `CINEMA_AGENT_RULES.md` — mandatory restrictions, security requirements, coding standards, and testing rules.
3. `CINEMA_AGENT_SKILLS.md` — recommended skill guidance and implementation workflow.

## Initial task

Do not immediately start generating the application.

First:

1. Inspect the repository, current Git status, installed dependencies, environment configuration, existing frontend and backend code, database migrations, and tests.
2. Identify what is already implemented and what is missing.
3. Compare the current codebase with the project specification.
4. Propose a phased implementation plan with dependencies, risks, and test criteria.
5. Identify architectural decisions that genuinely require clarification.
6. Present the plan and wait for approval before beginning major implementation or destructive changes.

## Development workflow

Implement the application incrementally, prioritizing a complete and tested booking journey over superficial feature breadth.

For each phase:

- Explain the objective.
- Implement a coherent feature across the necessary layers.
- Run relevant tests, lint checks, and builds.
- Investigate and fix failures.
- Review security, authorization, accessibility, and edge cases.
- Summarize changed files and verification results.

Do not claim completion without evidence.

## Final objective

Deliver a working, maintainable, secure, responsive cinema reservation application that satisfies the project specification and its acceptance tests. Report any remaining limitations honestly.
